## 1. 연달아 예약(1박2일씩) 시 마지막 퇴실일이 빈칸으로 보이던 문제 수정

### 증상
"28일 입실 29일 퇴실, 29일 입실 30일 퇴실"처럼 예약이 연달아 있으면 28일·29일은 정상 표시되지만 30일(두 번째 예약의 퇴실일)에는 아무것도 표시되지 않음.

### 원인
달력 칸에 예약을 표시하는 로직이 `check_in <= date < check_out`(그 날짜 밤에 묵는 예약)만 찾고 있었음. 퇴실일 자체는 "그 밤에 묵는 예약"이 아니므로, 뒤이어 새로 체크인하는 예약이 없으면 그냥 빈칸으로 보임.

### 수정 (`public/app.js`, `public/style.css`)
- 기존 "묵는 예약(matches)" 표시는 그대로 유지 (빈 날짜 클릭 시 새 예약 등록 가능 여부 판단에도 계속 사용).
- 별도로 "그 날짜에 퇴실하는 예약(departures)"을 찾아서 `손님이름 퇴실` 형태의 태그를 추가로 표시하도록 함. 연한 회색 이탤릭 스타일(`.reservation-tag.checkout`)로 구분해서, 그 밤에 묵는 예약(파란 배경)과는 다르게 보이도록 함.
- 클릭하면 기존과 동일하게 해당 예약 상세가 열림.
- 퇴실만 있는 날짜(새 체크인 없음)에 빈 곳을 클릭하면 여전히 새 예약 등록이 가능함 (departures는 클릭 로직에서 제외했기 때문).

### 요금 색상 통일 (`public/style.css`)
기존에는 요일 요금표 기본 가격은 회색, "요금 입력"으로 등록한 예외 가격(daily_rates)은 주황색 굵은 글씨로 다르게 표시됐는데, 사용자 요청으로 모두 같은 회색으로 통일함 (`.day-rate-override` 규칙 비움).

배포: `public/app.js`, `public/style.css` 커밋 (`3b41617`). 사용자가 `git push` 후 VPS `git pull` + `pm2 restart myapp`으로 배포.

## 2. 같은 방에 하룻밤 중복 예약 방지

### 요청 배경
바깥채 9월 29일에 두 팀이 동시에 예약되어 있는 것을 사용자가 발견. "한 방에는 하룻밤에 한 팀만 예약 가능해야 한다"는 규칙이 지금까지 강제되고 있지 않았음.

### 구현 (`routes/reservations.js`)
- `findOverlappingReservation(pensionId, checkIn, checkOut, excludeId)` 헬퍼 추가: 같은 펜션(방)에서 날짜가 하룻밤이라도 겹치는 다른 예약이 있는지 조회.
- `POST /api/reservations`(신규 등록), `PUT /api/reservations/:id`(수정) 양쪽에 이 검사를 추가. 겹치는 예약이 있으면 409 상태코드와 함께 "같은 기간에 이미 예약이 있습니다: OOO님 (9/28 ~ 9/30). 한 방에는 하룻밤에 한 팀만 예약할 수 있습니다." 형태의 메시지를 반환.
- 수정(PUT) 시에는 먼저 기존 예약 row를 조회해서 최종 `check_in`/`check_out`(일부만 수정하는 경우 기존 값과 합쳐서)을 확정한 뒤 겹침을 검사하고, 자기 자신은 비교 대상에서 제외.

### 프론트 (`public/app.js`)
- 저장 버튼 클릭 시 서버가 409/400 등 오류를 반환하면, 기존의 뭉뚱그린 "저장 실패. 콘솔을 확인해주세요." 대신 서버가 보낸 구체적인 메시지를 그대로 alert로 보여주도록 수정.

### ⚠️ 배포 전 주의사항 안내
바깥채 9/29의 기존 중복 예약 2건을 먼저 정리하지 않고 이 코드를 배포하면, 겹쳐 있는 두 예약 중 하나를 수정하려 할 때마다(날짜를 안 바꿔도) "겹치는 예약이 있다"며 저장이 막힌다는 점을 사용자에게 안내함. 사용자가 "직접 정리하겠다"고 답변해서, 기존 데이터 정리는 사용자가 직접 진행하기로 함 (이 세션에서는 로컬 VM에서 DB(192.168.1.21)로 직접 접근이 안 되어 — `ENETUNREACH` — 어떤 두 예약인지 직접 조회할 수 없었음).

배포: `public/app.js`, `routes/reservations.js` 커밋 (`9aa761c`).

## 3. 관리자 페이지에 데이터 백업/복원 기능 추가

### 구현 (`routes/admins.js`)
- `GET /api/admins/backup`: 현재 모든 예약(reservations)과 날짜별 예외 요금(daily_rates)을 JSON으로 내려받음. 파일명은 `pension-backup-YYYY-MM-DD.json`. 각 예약/요금 항목은 `pension_id` 대신 `pension_name`(사랑채/별채/바깥채)으로 저장해서, 나중에 복원할 때 DB의 펜션 id가 지금과 달라도 이름으로 다시 연결되도록 함. 관리자 계정(admins) 정보는 비밀번호 해시가 포함되므로 백업에서 제외.
- `POST /api/admins/restore`: 업로드된 백업 JSON을 검증(형식 확인 + 백업 안의 펜션 이름이 현재 DB에 모두 존재하는지 확인) 후, 트랜잭션 안에서 현재 `daily_rates`, `reservations`를 전부 지우고 백업 내용으로 새로 채워 넣음. 하나라도 알 수 없는 펜션 이름이 있으면 아무것도 지우지 않고 바로 400 오류로 중단.
- `server.js`의 `express.json()` 본문 크기 제한을 기본값(100kb)에서 `10mb`로 늘림 (큰 백업 파일 업로드 대비).

### 프론트 (`public/admin.html`, `public/admin.js`, `public/style.css`)
- "회원 관리" 섹션 아래에 "데이터 백업/복원" 섹션 신규 추가.
- "백업 다운로드" 버튼: `fetch`로 받은 JSON을 Blob으로 만들어 자동 다운로드.
- 파일 선택 + "이 파일로 복원" 버튼: 파일을 선택하고 누르면 "되돌릴 수 없다"는 confirm 팝업이 뜨고, 동의하면 백업 JSON을 서버로 전송해서 복원 실행. 결과 메시지(성공/실패)를 화면에 표시.
- 이 기능은 관리자 페이지 자체가 시스템 관리자 전용이라 별도 권한 처리 없이 자동으로 시스템 관리자만 사용 가능.

배포: `public/admin.html`, `public/admin.js`, `public/style.css`, `routes/admins.js`, `server.js` 커밋 (`4781afd`).

## 오늘 작업 중 있었던 이슈 (참고용)

- **git 커밋 시 `.git/index.lock` 파일이 남아 있어 커밋이 막힌 적 있음** — 이전 `git add` 과정에서 파일 삭제 권한이 없어(`Operation not permitted`) 임시 lock 파일이 정리되지 못하고 남았던 것. `device_request_delete_permission`으로 해당 폴더(`C:\WR\code\claude\myapp`)에 대한 삭제 권한을 사용자에게 요청해서 승인받은 뒤 `rm -f .git/index.lock`으로 해결.
- **이 device_bash 환경에는 git 사용자 정보(user.name/user.email)가 설정되어 있지 않아서 첫 커밋 시도 시 "Author identity unknown" 오류 발생** — 저장소 로컬 설정(`git config user.name/email`, `--global` 아님)으로 사용자 계정 정보(JIJ / jycheong@gmail.com)를 지정해서 해결. 다음 세션에서도 이 설정이 유지되는지 불확실하니, 만약 다시 이 오류가 나면 같은 방식으로 해결하면 됨.
- **로컬 VM에서 실제 DB(192.168.1.21:5432)로 직접 접근이 안 됨(`ENETUNREACH`)** — 그래서 바깥채 9/29 중복 예약이 정확히 어떤 손님들인지 이 세션에서는 직접 조회하지 못했음. DB 데이터를 직접 들여다봐야 하는 작업은 여전히 이 방식으로는 불가능함 (npm 레지스트리 접근 제한과 마찬가지로 이 VM의 네트워크 제약으로 보임).
