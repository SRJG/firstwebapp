- "복원": 백업 파일을 선택해서 업로드하면, 확인 팝업(되돌릴 수 없다는 경고 포함) 후 현재 예약/요금 데이터를 전부 지우고 백업 내용으로 교체. 펜션은 이름으로 매칭해서 복원하므로, 백업에 모르는 펜션 이름이 있으면 아무것도 지우지 않고 바로 중단됨.
- 시스템 관리자만 사용 가능 (관리자 페이지 자체가 시스템 관리자 전용).

## 오늘 새로 확인된 사실 (다음 세션 참고용)
- **로컬 VM(device_bash)에서 실제 DB(192.168.1.21:5432)로 직접 접근 불가** (`ENETUNREACH`). npm 레지스트리 접근 제한과 마찬가지로 이 VM의 네트워크 제약으로 보임 — DB 데이터를 직접 조회/확인해야 하는 작업은 이 방식으로 할 수 없고, 사용자에게 직접 확인을 부탁하거나 앱 UI/API를 통해서만 간접 확인 가능.
- **device_bash 환경엔 git 사용자 정보(user.name/user.email)가 기본적으로 설정돼 있지 않음** — 커밋 시도 시 "Author identity unknown" 오류가 났고, 저장소 로컬 설정(`git config user.name/email`, 글로벌 아님)으로 JIJ / jycheong@gmail.com을 지정해서 해결함. 다음 세션에서도 유지되는지는 불확실하니 같은 오류가 나면 같은 방식으로 재설정할 것.
- **git add/commit 도중 삭제 권한이 없어(`Operation not permitted`) `.git/index.lock` 같은 임시 파일이 정리되지 않고 남아 커밋이 막힐 수 있음** — `device_request_delete_permission`으로 프로젝트 폴더에 대한 삭제 권한을 사용자에게 요청해서 승인받은 뒤 `rm -f .git/index.lock`으로 해결. 다음에 비슷한 "index.lock" 오류가 나면 같은 방법 사용.
- `device_bash`는 계속 정상 작동 중 (9/19부터).

## device_bash 안 될 때 (예전 방식)
로컬 PC로 파일을 쓰는 `device_commit_files`가 가끔 "성공(written)"이라고 응답하면서도 실제로는 반영이 안 되는 현상이 있었음. 파일을 쓸 때는 commit 후 `device_stage_files`로 다시 읽어서 md5 체크섬까지 대조 확인하고, 불일치 시 `force: true`로 재시도할 것. "written" 응답만 믿지 말 것.

- 이 Claude 세션은 로컬 PC에만 연결돼 있어 VPS는 직접 접근 불가 (사용자가 SSH로 직접 실행/확인해야 함)
- 로컬 VM(device_bash)은 npm 레지스트리, 로컬 네트워크 DB 등 외부 접근이 제한적임 — git push도 안 됨 (프록시에서 403). git add/commit까지는 device_bash로 가능하지만, `git push`는 사용자가 실제 Windows 터미널에서 직접 실행해야 함.
- cmd.exe에서는 작은따옴표(')가 안 먹히니 커밋 메시지 등은 큰따옴표(") 사용할 것
- 새 파일 여러 개를 추가하는 커밋을 안내할 때는 `git add` 목록을 준 뒤 `git status`로 빠진 파일이 없는지 한 번 더 확인할 것
